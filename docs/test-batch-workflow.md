# 上流テスト起点の互換実装

1. 統合版の SHA を固定する。6 担当は未移植ケースを機能単位でまとめて準備する。バッチでは互換実装を進めず、期待値、入力、展開済みパラメーター、実行コマンドを揃える。
2. 固定 SHA からビルドした同じ penv バイナリで各担当のバッチを並列実行する。実行できたケースの合否と、ロード前や共通設定で止まったケースを区別する。準備できないケースも出典、阻害点、未実行理由を記録する。
3. すべての担当結果を集め、失敗を最初の共通原因で束ねる。同じ共有コードを触る修正は一つのグループにまとめ、別の実装経路で作業できるグループは 6 体に並列で割り振る。共有の統合窓口は ARM 担当とする。
4. 修正を統合し、同じテスト、入力、判定条件で全バッチを再実行する。前後で実行可能数、合格数、残る原因を比較する。

固定 SHA、作業ツリーとバイナリの場所は `~/.local/state/penv-dispatch/baseline/current.tsv` に記録する。各担当のケース結果には出典、構成、期待値、実測、合否または実行阻害、再現コマンド、ログを含める。複数ケースが同じ設定エラーで止まったときも、影響を受けるケースを台帳から追跡できるようにする。
